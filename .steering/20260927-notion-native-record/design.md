# 設計: Notion内で完結する記録フロー

**作成: 2026-09-27**

## Notion Plus で使える機能（調査確定事項）
- **Public API: Plusで使える**（現行GAS同期が稼働＝実証）。Businessは上限UPのみ（Plus 180req/分, Business 600req/分）。→ Business課金は不要。
- **DBオートメーション/ボタンで Send webhook: 全有料プラン(Plus含む)で可**（ヘルプ webhook-actions）。ただし料金ページは「Plusはボタンのみ」と矛盾表記あり→実機確認推奨。
- **ボタン・オートメーション・DBテンプレートは UI専用＝API/MCPで作成不可**（update-data-source に BUTTON型なし）。
- **数式 `link("表示","URL")`** はクリック可能リンクを動的生成でき FORMULA型なのでAPIで作成可。ただしiPad Notionアプリでのタップ挙動が不安定（今回、予約サイトへのキャッシュ/リンクしか出ない事象が発生）。
- 顧客DBには既にネイティブrollup（累計来院回数・最終来院日）が稼働。

## 重要な制約と結論
- 「サイトに飛ばずNotion内で完結」に必要なのはボタン or オートメーション。**どちらもNotion UIでしか作れず、当環境ではブラウザ自動化のスクリーンショットが真っ黒でキャプチャ不可のため、Claudeが代理でUI作成するのは困難**。
- したがって推奨は「**ネイティブのリレーション作成＋GASバックグラウンド同期**」。ボタン不要で今すぐ使え、UI手作業が最小。

## 推奨アーキテクチャ（案N: ネイティブ・リレーション＋GASポーリング）

### ルカスの操作（すべてNotion内・サイトに飛ばない）
1. 顧客管理DBで来店客を検索して開く。
2. 顧客ページの **「施術カルテ」リレーション** で「＋ 新規ページ」→ 新カルテが**その顧客に自動リンクされて**生成（Notionリレーションの標準挙動、設定不要）。
3. 新カルテで入力: 日付→今日 / 前回から変化(なし/あり) / コース / 売上金額 / 支払い方法 / 施術メモ / ステータス→✅完了。
4. （高速化）施術カルテDBに**データベーステンプレート**を作ると、ステータス=未記録等の既定値をワンタップで入れられる（UI作成・任意）。

### バックエンド（GAS・不可視）
- GASの時間トリガーで施術カルテDBを**ポーリング**（Plusでも Notion API 読取可）。
- 新規/更新された「ステータス=✅完了」かつ未取込のカルテを検出 → シート台帳(施術台帳)へ記録 → クレジット残高/紹介上限/売上を計算 → Notionへ書き戻し（残高等）。
- 冪等性: NotionページIDで取込済み管理（施術台帳に notion_page_id を突合、または取込済みフラグ）。
- 代替(リアルタイム): カルテに「確定」ボタン(UI手動作成)を置き Send webhook→GAS。Plusで可だがボタン手作成が必要。

### お金のSource of Truth
- 変わらずシート台帳。GASがNotion→シートの一方向取込＋計算結果をNotionへ書き戻し（CLAUDE.md旧ルール「Notion→シート逆同期禁止」を本再設計で解禁）。

## 代替案（不採用/保留の記録）
- **案②数式URLリンク→Webアプリ**: 実装・デプロイ済みだが、ユーザーが「サイトに飛ぶのは嫌／Notion内完結希望」で方針転換。iPadでリンクが予約サイトしか出ない事象もあり。→ 保留。
- **案①ネイティブButton**: UI手作成必須、当環境のブラウザで作成困難。別PC（画面が見える環境）でなら手順書通り2分で作成可能。
- **Make/Zapier**: APIポーリングで可だが遅延（無料15分）・別サービス。不採用。
- **Businessアップグレード**: 不要（Plusで足りる）。

## 別PCで「Button方式」を作る場合の手順（画面が見える環境向け）
1. 顧客管理DBに新規プロパティ → 種類「ボタン」→ 名前「本日カルテ作成」。
2. アクション「ページを追加する」→ 対象DB=施術カルテ。
3. 追加ページのプロパティ: 顧客マスタ=このページ / 日付=今日 / ステータス=🔴未記録。
4. （任意）「確認画面を表示」。
5. 保存。テスト顧客(P008/P031)で動作確認。
