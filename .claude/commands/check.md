品質チェックを実行します。

## 実行する内容

### 1. GAS の構文チェック(dry-run)

```bash
~/.local/bin/clasp status
```

送信予定のファイルと差分を表示します。**この時点では push しません。**

### 2. HTML/JS の構文確認

主要ファイルの JS ブロックが構文エラーなく読み込めるかを目視で確認します。

- `questionnaire.html`
- `treatment-record.html`
- `dashboard.html`
- `face-auth-test.html`

### 3. 変更ファイルの一覧

```bash
git status --short
git diff --stat
```

## 手順

1. 上記を順に実行する
2. **どれか1つでも失敗したら、そこで止めて報告する**
3. すべて通ったら、その旨を報告する

## 失敗したときの報告

```
❌ [チェック名] で失敗しました。

エラー内容:
(該当箇所)

原因:
(推測される原因)

修正案:
(どう直すべきか)
```

**勝手に修正しないでください。** 報告して指示を待ってください。

ただし、明らかな軽微なもの(コメントの typo・末尾スペース等)は
修正したうえで「修正しました」と報告して構いません。

## すべて通ったとき

```
✅ すべて通りました。

clasp status : 差分 N ファイル(内訳:...)
HTML syntax  : OK
git diff     : N ファイル変更
```

## 次のステップ

`/check` が通っても、それだけでは push されません。
本番反映は必ず `gas-ops` エージェント経由で Nicolas の許可を得てから行ってください。
