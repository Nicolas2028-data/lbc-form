要求内容 — 顔認証廃止と来店フロー刷新

作成日: 2026-09-26 作業名: 顔認証廃止と来店フロー刷新 起票の背景: ルカスの要望メモ(LBC_要望メモ_ルカス_20260906、2026-09-13 更新)+ LINE でのやりとり(2026-09-09〜09-23)

何をするか(要約)

  1. 顔認証機能を全廃止する — Phase A〜D で実装した全機能を削除。認証は電話番号+氏名のみに一本化。
  2. 来店ログタブを新設する — 患者が問診票を送信した時点で「本日来店」として記録。ルカスの記録抜け漏れ防止に使う。
  3. 施術記録シートに「施術有無」トグルを追加する — no-show を明示的に記録できるようにする(理由入力欄付き)。
  4. Notion 側にルカス向けの視認性高いダッシュボードを構築する — 未記録リスト(カンバン形式)+ TODAY サマリ + 状態別カラー表示。
  5. 記録漏れ検知ロジックを追加する — 全期間の未記録レコードを常時可視化。

背景

顔認証を廃止する理由

  • 月6〜12人規模に対して 128次元 embedding + Kiosk 4連タップ unlock は明らかに過剰
  • ルカスから「そもそも2回目の来院時には Notion で自分がお客様情報を見るついでに記録できた方がお客様の手間も少ない」と要望
  • 電話番号+氏名照合(Step 2-3 で実装済み)で運用上十分

来店ログを新設する理由

  • ルカスの主な困りごとは「記録し忘れ」
  • 予約日 ≠ 来店日(no-show やキャンセルがある)ため、来店確定のシグナルが必要
  • 既存の問診票送信を「来店の意思表示」として使えば追加 UI が不要
  • Notion 上で「未記録リスト」を可視化することで書き忘れゼロ運用を目指す

変更・追加する機能

追加

  • 来店ログタブ (来店ログ) をシートに新設
    • checkin_id / customer_id / checkin_at / checkin_date / recorded_at / record_id / treatment_record_url / no_show_reason / updated_at / synced_at
  • Notion 来店ログ DB を新設(既存 3 DB + 1)
    • プロパティ: 状態 (Status)、顧客名 (Title)、来店 (Date)、経過 (Formula)、📝 記録する (URL)、メモ (Text)
    • ビュー: 未記録ビュー(Board / カンバン)、今日の来店ビュー(Gallery)、全履歴ビュー(Table)
  • 施術記録シートに「施術有無」トグル
    • 「施術を受けた」/「施術を受けなかった」ラジオボタン
    • 「受けなかった」選択時は施術内容欄を非表示、理由入力欄を表示
  • 問診票送信時の来店ログ書き込み
    • 初回問診票: 全項目送信 + 来店ログ 1行追加(status=received)
    • 再来院問診票: 電話番号+氏名照合成功 → 来店ログ 1行追加
  • 施術記録受信時の recorded_at 更新
    • 同日・同 customer_id の来店ログレコードを探して recorded_at と record_id を書く
    • 該当なしの場合: 来店ログを自動補完(通知メールで一報)
  • normalizeName() 関数 — 全角半角スペース統一、前後トリム
  • 送信後 UI メッセージ — 「✅ 記録しました。1分以内に Notion に反映されます」
  • Notion ダッシュボードページ の再構成
    • 大型カバー画像 (LBC ブランドカラー)
    • TODAY サマリ callout(未記録数を大きく表示)
    • 未記録リスト Board View(本日 / 1日経過 / 2日以上 の3列)
    • 今日の来店 Gallery View
    • 未記録0件時の「🎉 ALL DONE!」callout

  • questionnaire.html の顔認証関連 UI 全般(顔登録同意、顔照合ボタン、Kiosk 4連タップ unlock、staff password モーダル、顔認証モーダル)
  • gas/Code.js の顔認証関連関数
    • handleGetFaceEmbeddings
    • handleMatchFace
    • handleSaveFaceEmbedding(存在すれば)
    • handleHasFaceEmbedding(存在すれば)
    • doPost の顔認証系 action 分岐
  • face-auth-test.html(参考用プロトタイプ)
  • palm-auth-test.html(参考用プロトタイプ)
  • i18n/{ja,es,pt}.json の顔認証キー全般
  • SPEC.md の 11.5 顔認証セクション
  • customers タブの face_embedding 列(判断: 物理削除 / 空文字化のいずれか。Nicolas 判断)

変更(据え置き)

  • index.html は一切触らない(既存原則)
  • 予約系 API は触らない(既存原則)
  • 電話番号+氏名照合ロジックは既存のものを維持(normalizeName の追加のみ)

受け入れ条件

顔認証廃止

  • 全ファイルから顔認証関連コード・UI・文言・SPEC 記述が消えている
  • questionnaire.html を開いても顔認証ボタン・kiosk unlock が表示されない
  • gas/Code.js に顔認証系関数・action 分岐が残っていない
  • face_embedding 列の扱い(削除 or 空文字化)が Nicolas 判断で確定している
  • 3言語(ja / es / pt)の翻訳キーからも顔認証関連が消えている
  • 顔認証削除後に既存の電話番号+氏名照合フローが動く(staging で確認)

来店ログ

  • 来店ログ タブがシートに存在し、指定スキーマで作成されている
  • 初回問診票送信 → 来店ログに1行追加される
  • 再来院問診票送信 → 来店ログに1行追加される
  • 施術記録シート(施術を受けた)送信 → 該当来店ログの recorded_at が更新される
  • 問診票なしで施術記録が送信された → 来店ログが自動補完される + 通知メールが届く
  • no-show(施術を受けなかった)送信 → 台帳に no_show 行 + 来店ログの recorded_at 更新 + no_show_reason 記録

Notion ダッシュボード

  • 未記録リスト Board View が「本日 / 1日経過 / 2日以上」の3列で表示される
  • 記録完了後 1分以内にビューから該当レコードが消える
  • TODAY サマリに未記録数・記録済み数・施術なし数が表示される
  • 未記録リストが空のとき「🎉 ALL DONE!」callout が表示される(または未記録件数が0と目視できる)
  • 状態プロパティが色付き Status ラベルで表示される
  • 経過日数が Formula で「本日」「1日経過」「N日経過」と表示される
  • 「📝 記録する」URL をクリックすると treatment-record.html が名前・電話番号事前入力で開く

ロジック整合性(思考実験で洗い出したもの)

  • 訂正モード(赤伝)実行時、来店ログの recorded_at は維持される
  • 名前の表記揺れ(全角/半角スペース)で照合失敗しない(normalizeName)
  • 施術記録送信後の UI に「1分以内に Notion 反映」表示が出る
  • 1日2回来店(稀ケース)で checkin_id が個別発行され、古い順にマッチする

制約事項

  • index.html(予約フォーム)は一切触らない
  • シートが正の原則を維持 — Notion からの逆同期は一切行わない
  • 台帳は追記専用 — 来店ログの recorded_at 更新は「集計対象フラグ更新」相当の限定的な既存行編集として許容(SPEC 3.5 と同じ扱い)
  • 費用制約 — 全て無料枠(GAS / Sheets / Notion)を維持
  • STAFF_PASSWORD 認可 — 施術記録・スタッフ系 API は既存通りサーバー側検証必須
  • iPad 運用 — 既存 iPad(Safari / Chrome)で動作すること
  • 3言語対応 — 問診票側は ja / es / pt を維持(施術記録シート・Notion 側は日本語+絵文字のみ)

Nicolas への確認事項

以下は 2026-09-26 会話ですでに確定:

  1. 1回目の患者の扱い → 全項目入力(現行のまま)。問診票送信 = 初回来店 & 記録待ち
  2. 2回目以降の入力項目 → 電話番号+氏名の両方必須
  3. 来店ログの保存場所 → 独立タブ(施術台帳との相乗りではない)
  4. 未記録リストの期間 → 全期間表示(古い書き忘れも見える)
  5. no-show の扱い → 施術記録シート内「受けた/受けなかった」トグル + 理由入力
  6. 問診票なしで施術された場合 → 原則NG(現場ルール)、システム的には自動補完で吸収
  7. Notion 見せ方 → 派手バージョン(カバー画像 + Board View カンバン + TODAY サマリ callout)
