# 要件: LBC Care 基盤の作り直し(GAS + シート + Notion → 本格アプリ)

**作成: 2026-10-03 / ステータス: Nicolas 承認済み (2026-10-03)**

## 1. 背景

### 1.1 直接のきっかけ(2026-10-03 計測)
本番 GAS(@141)の読込 API を約 30 回計測した結果:

- GAS 内の処理(doPost)は毎回 **1.5〜4.5 秒・全件成功**(実行ログで確認)
- しかしクライアントから見ると **約 1 割が 20〜60 秒の遅延、または失敗**(Google のエラーページ「ページが見つかりません」、リダイレクト異常で doGet に化ける)
- シートを読まない軽量リクエスト(認証で即拒否されるだけ)でも同様に失敗 → **原因は GAS Web アプリの受付層(Google 側)で、こちらのコードでは直せない**
- ネットワーク(google.com 応答 0.1〜0.4 秒)、1 分毎の syncToNotion とは無関係

ルカスの日常業務(施術記録)で「たまに失敗する」「再読み込みが必要」は許容できない。

### 1.2 構造的な問題
現行はデータ=シート、処理=GAS、表示=Notion の継ぎ合わせ。今後の機能追加(下記 3 章)では、
同期のズレ・型のないデータ・5,000 行の単一ファイル(gas/Code.js)が限界になる。

### 1.3 検討して却下した案
| 案 | 却下理由 |
|---|---|
| 現行の記録シートにリトライ・ローカルキャッシュを追加 | 不安定な土台の上の対症療法。複雑化するだけで根本解決しない |
| Notion で記録 → GAS が裏で取込(Notion 中心案) | 入力時の検証不可・結果反映に最大 1 分遅延。今後の機能(決済・予約枠・マイページ)を載せられない |

## 2. 目的

1. スタッフ・顧客が使う画面が **常に速く(目安 1 秒以内)、失敗しない** こと
2. 今後の機能(3 章)を **無理なく積み増せる土台** にすること
3. お金・予約の **正しさをデータベースのレベルで保証** すること(二重予約・二重記録・残高不整合が起きない)
4. 運用費は **なるべく無料**(4.4)

## 3. スコープ

フェーズ分けはしない。以下を **すべて新システムの対象** とし、作る順番は design.md / tasklist.md で決める。
データ構造は最初から全機能を受け入れられる形で設計する(店舗 ID・スタッフ ID・取引の記録方式など)。

## 4. 非機能要件

### 4.1 性能・信頼性
- スタッフ画面の読込・送信: 通常 **1 秒以内**、悪くても 3 秒以内
- 一時的な通信失敗でも **入力内容を失わない・二重記録しない**(送信は冪等)
- iPad の回線が一瞬切れても、施術記録の入力途中のデータが消えない

### 4.2 データの正しさ
- お金(売上・クレジット・回数券・決済)は **取引記録の積み上げ** で表す。残高は上書きせず記録から導出する
- 訂正は赤伝方式(取消+訂正の記録を追加)。物理削除しない
- 二重予約・同一 requestId の二重記録はデータベースの制約で防ぐ

### 4.3 セキュリティ・個人情報
- 問診内容は **要配慮個人情報(健康情報)**。閲覧できるのはスタッフのみ、顧客は自分のデータのみ
- 権限はサーバー(データベース)側で強制する。画面での出し分けは補助
- データは日本リージョンに置く
- 公開ソース(GitHub)に秘密情報を置かない
- 個人情報を外部 AI に送らない(現行方針を継続)

### 4.4 コスト
- **月額固定費は原則 0 円**(無料枠で運用)
- 無料枠の制約で受け入れるもの・対策するものは design.md で明記する(例: 自動バックアップなし → 自前の日次バックアップで補う)
- 従量課金(決済手数料・LINE の追加通数など)は利用に比例するもののみ許容
- **商用利用が禁止されている無料枠は使わない**

### 4.5 多言語
- ja / es / pt の 3 言語。文言追加時は 3 言語同時に更新(現行ルール継続)

### 4.6 環境
- **テスト環境と本番環境を分ける。** 新システムはテスト環境で開発し、受け入れ確認後に本番を開始する
- 現行システム(GAS)は新システムの本番開始まで現状維持(新規の機能追加はしない)

### 4.7 保守性
- Nicolas + Claude Code で保守できること(一般的な技術・型付きの言語・自動テスト)
- 1 ファイルに全ロジックを詰めない

## 5. 受け入れ条件

1. テスト環境で、ルカスが iPad から ログイン → 患者検索 → 施術記録 → 送信 まで、**体感で待たずに** 完了できる
2. 計測で、スタッフ画面の主要操作の 95% が 1 秒以内、失敗 0 件(通信断のテストを含む)
3. 現行台帳から移行したデータで、顧客数・来院数・売上合計・顧客ごとのクレジット残高が現行と一致する
4. クレジットの業務ルール(FIFO、1 年失効、紹介 3 件上限、残高超過の拒否、赤伝訂正)がテストで検証されている
5. 予約・問診(ja/es/pt)が新システムで動き、GAS を止めても全業務が回る
6. 3.2 の新機能それぞれの受け入れ条件を design.md で定義し、それを満たす
7. 日次バックアップが自動で取られ、そこから復元できることを 1 回確認している
8. 月額固定費 0 円で運用できている(または例外を Nicolas が承認済み)
