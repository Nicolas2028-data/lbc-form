1システム概要とデータフロー

3つのHTMLページ（予約・問診票・施術記録）がGAS（Googleスプレッドシート連携なし・Notionに直接書込み）を経由し、2つのNotionデータベースへデータを蓄積します。

PART 2
各HTMLの役割と操作フロー
問診票・施術記録シートのUI/UXロジック

4問診票（questionnaire.html）

来院時にiPadで記入。スタンドアロン運用（URLを直打ちして開く）。日本語・スペイン語・ポルトガル語対応。

操作フロー

  1. 言語選択
  2. 基本情報入力（氏名・フリガナ・電話・生年月日・性別）
  3. 既往歴・アレルギー・主訴などの問診セクション
  4. 人体図（Canvas）で痛む箇所をタッチ/マウスで塗る
  5. 署名（Canvas）に手書きサイン
  6. 送信 → GAS submitQuestionnaire
  7. GASが人体図・署名をbase64 → Google Driveに保存 → 共有URLをカルテDBに記録
  8. カルテDBに本日分のカルテを新規作成（コース・売上は空欄）
注意：コース選択は問診票に含まれません。施術記録シートで選択します。問診票送信時点のカルテはコース未設定の状態で作成されます。

5施術記録（treatment-record.html）

ルカス専用・日本語のみ。施術後にiPadで記録。パスワード認証あり（GASスクリプトプロパティ STAFF_PASSWORD）。

6-1. PHASE 1：患者検索

  1. パスワード入力（正解でのみPhase 1に進む）
  2. getPatientList で全患者を取得しリスト表示
  3. 患者番号・氏名で絞り込み検索
  4. 患者を選択 → getPatientDetails で詳細取得
  5. Phase 2 に遷移（患者バナーに来院回数・最終来院日を表示）

6-2. PHASE 2：施術入力

  1. コース選択（6択）
  2. 支払い方法選択（現金 / カード / 未払い）
  3. 月2回プラン追加オプション（±¥10,000）
  4. 紹介者入力（初回来院の場合のみ表示）
  5. クレジット使用設定（¥1,000単位のステッパー）
  6. 施術メモ入力
  7. 金額サマリ自動表示（ベース + 追加 − 紹介割引 − クレジット）
  8. 送信 → submitTreatmentRecord

6-3. 初回来院フラグ（isFirstVisit）

getPatientDetails が返す visitCount === 0 のとき isFirstVisit = true。

初回来院（isFirstVisit = true）
  • 紹介者入力セクションを表示
  • 紹介割引（¥1,000引き）が適用可能
  • クレジット残高があっても使用不可（初回=クレジット未保有のため）
2回目以降（isFirstVisit = false）
  • クレジット使用可能（¥1,000単位で最大残高まで）
  • 紹介割引は適用不可
  • 紹介者入力セクションは非表示

7月2回プランロジック

月定額¥10,000で同月に2回施術できるプラン。トータルケアが主な対象（¥6,000×2=¥12,000の価値）。

8-1. 2つのパターン

パターン A

月額を一括払いする

1回目にコース（¥4,000〜6,000）を選び、追加で月2回プラン（+¥10,000）チェックを入れる。
支払合計 = コース料金 + ¥10,000。
2回目は「月2回プラン（2回目・前払済）」= ¥0。

パターン B

月2回プランとして一括選択

「月2回プラン（今月2回カバー）」を直接選択。¥10,000を支払う。
2回目は「月2回プラン（2回目・前払済）」= ¥0。

8-2. 施術記録の記録ルール

回UIでの選択Notion courseId売上金額
1回目（パターンA）例：トータルケア + 月2回プラン追加トータルケア¥16,000（6,000+10,000）
1回目（パターンB）月2回プラン（今月2回カバー）月2回プラン¥10,000
2回目（どちらも）月2回プラン（2回目・前払済）月2回プラン¥0
2回目の扱い：売上金額¥0・支払い方法「未払い」として記録。クレジット使用・紹介割引は2回目には適用不可（前払済のため割引する必要がない）。

8-3. 月カウントの考え方

月内の何回目かはNotionのカルテDBをカレンダービューで確認する（GASが自動集計はしない）。ルカスが目視で判断して「2回目・前払済」を選ぶ運用です。

8紹介割引ロジック

患者が友人・知人を紹介し、その紹介された人が初来院したとき、紹介した患者（紹介者）に¥1,000クレジットが付与されます。紹介された患者（被紹介者）には¥1,000引きの割引が適用されます。

9-1. 適用条件

紹介者（クレジット付与される側）
  • 既存患者であること
  • 被紹介者が実際に初来院したこと
  • 何人でも紹介可能（上限なし）
  • クレジット有効期限：獲得日から1年
被紹介者（割引される側）
  • 初回来院であること（isFirstVisit = true）
  • 施術記録で紹介者を選択・入力
  • ¥1,000引き（紹介割引）が適用される
  • 同一患者への紹介割引は1回限り
  • クレジットとの同時使用不可

9-2. 施術記録での操作

  1. 患者が初回来院（isFirstVisit = true）のとき、Phase 2 に紹介者セクションが表示される
  2. ルカスが紹介者名を検索（患者一覧から選択）
  3. 「紹介割引適用」がONになり、金額から¥1,000引き
  4. 送信後 GAS が：
      ① カルテDBに 紹介者名・紹介割引適用=true を記録
      ② 紹介者の カスタマーDB に addCredit(¥1,000) を実行

9-3. GAS addCredit 処理

// addCredit(cfg, referrerId, 1000) の処理内容
1. 紹介者の Notion ページ取得（customerId = referrerId）
2. クレジット詳細（JSON文字列）を取得・パース
3. { "date": "今日の日付", "amount": 1000 } を配列に追記
4. 配列全体の amount 合計 = 新しいクレジット残高
5. Notion PATCH: クレジット残高（number）・クレジット詳細（rich_text）を更新

9クレジットシステム

紹介によって貯まる院内クレジット。¥1,000単位で施術料金から差し引けます。有効期限は獲得日から1年。60日前に警告表示されます。

10-1. クレジットのライフサイクル

獲得: 紹介者が被紹介者の初来院時に +¥1,000 付与
  ↓
保管: カスタマーDB「クレジット詳細」に JSON で記録
       [{"date":"2026-07-25","amount":1000}, ...]
  ↓
警告: 有効期限60日前 → 施術記録シートにオレンジ警告表示
  ↓
消費: 患者が施術時に使用（¥1,000単位・ステッパーで選択）
       → FIFO（古い順）で消費
  ↓
期限切れ: 獲得日から1年経過 → Notionで手動削除（A案）

10-2. FIFO消費のイメージ

クレジット残高が¥3,000あり、¥2,000を使用する場合：

2025-07-15
¥1,000
消費
2025-09-01
¥1,000
消費
2026-01-20
¥1,000
残留

獲得日が古いものから順に消費。残留したクレジットのみ詳細JSONに残り、残高も更新されます。

10-3. GAS useCredit 処理

// useCredit(cfg, customerId, 2000) の処理内容（¥2,000消費の例）
1. 患者の Notion ページ取得
2. クレジット詳細 JSON をパース
3. date 昇順にソート（古い順）
4. 残り消費額 = 2000
   Loop:
     entry.amount <= 残り消費額 → entry を削除・残り消費額 -= entry.amount
     entry.amount >  残り消費額 → entry.amount -= 残り消費額・break
5. 新しい残高 = 残ったエントリの amount 合計
6. Notion PATCH: クレジット残高・クレジット詳細を更新

10-4. 有効期限管理（手動・A案）

期限切れクレジットの削除はルカスがNotionを直接編集して「クレジット詳細」JSONと「クレジット残高」を手動修正します。GASは自動削除しません。

60日警告の計算：getPatientDetails が各クレジットエントリの獲得日+1年を計算し、今日から60日以内に期限切れになるものを expiringCredits として返します。施術記録シートがオレンジ警告ボックスを表示します。

10-5. 適用制限

シナリオクレジット使用紹介割引
初回来院（紹介あり）不可適用可
初回来院（紹介なし）不可不可
2回目以降（クレジット残高あり）適用可不可
月2回プラン2回目（前払済）不可（¥0のため）不可
支払い方法：未払い不可（¥0のため）不可

10売上金額の計算ロジック（recalcAmount）

施術記録シートの金額欄は選択・入力に連動してリアルタイム自動計算されます。

// treatment-record.html recalcAmount() のロジック

basePrice   = 選択コースの定価（¥0〜¥10,000）
addonPrice  = 月2回プラン追加チェック時 +¥10,000（それ以外 ¥0）

// 未払いまたは月2回プラン2回目は全額¥0
isUnpaid = courseId === 'monthly2_2nd' || paymentMethod === '未払い'

referralDiscount = referralApplied ? 1000 : 0

// 未払い or 紹介割引適用中はクレジット使用不可
creditDiscount = (isUnpaid || referralApplied) ? 0 : creditUsed

// 最終金額（負にはならない）
total = isUnpaid ? 0 : Math.max(0, basePrice + addonPrice - referralDiscount - creditDiscount)

11運用チェックリスト

12-1. 初回セットアップ（一回のみ）

  1. GASエディタで addNotionFields() を実行し、5つのNotionフィールドを追加する
  2. GASを「新バージョン」としてデプロイする
  3. treatment-record.html の GAS_URL 定数がデプロイURLと一致しているか確認する
  4. GitHub Pages に push し、iPadで動作確認する

12-2. GAS更新時

  1. Code.gs を編集・保存
  2. デプロイ → デプロイを管理 → 鉛筆アイコン → 新バージョン → デプロイ
  3. URLが変わった場合は treatment-record.html の GAS_URL を更新して push

12-3. 月次運用（毎月）

  1. 月2回プランの1回目来院時：追加チェックまたは月2回プランコース選択
  2. 月2回プランの2回目来院時：「月2回プラン（2回目・前払済）」を選択（¥0記録）
  3. 期限切れクレジットがある患者：Notionのクレジット詳細・残高を手動更新

12-4. トラブルシューティング
